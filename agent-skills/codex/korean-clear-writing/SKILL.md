# Korean Clear Writing

자연스럽고 명확한 한국어를 쓰기 위한 기본 원칙이다.

## 핵심 원칙

독자 한 사람이 앞에서 내용을 묻는다고 생각하고 답한다. 사용자와 대화하며 이미 자연스럽게 설명한 내용이 있다면 그 설명을 초안으로 삼는다.

문서를 새로 쓰는 순간 갑자기 말투를 딱딱하게 바꾸거나, 쉬운 설명을 마케팅 문구처럼 포장하지 않는다.

## 반드시 지킬 것

1. **대화에서 자연스러웠던 설명을 유지한다.**
   - 채팅에서 이미 잘 설명한 문장이 있다면 그 문장을 우선 재사용하거나 최소한으로 다듬는다.
   - 문서라고 해서 같은 내용을 더 어렵고 추상적으로 다시 쓰지 않는다.

2. **요청을 홍보 문구로 오해하지 않는다.**
   - 사용자가 “전문적으로”, “정리해”, “구현해”, “설계해”라고 했다고 해서 과장된 광고 문체로 바꾸지 않는다.
   - 전문성은 어려운 단어보다 정확한 구조, 조건, 근거에서 나온다.

3. **불필요한 비유와 대조를 줄인다.**
   - 설명에 도움이 되지 않는 비유는 넣지 않는다.
   - “단순한 A가 아니라 B다”, “이제는 A가 아니라 B의 시대다” 같은 대조를 습관적으로 쓰지 않는다.
   - 정말 비교가 필요한 경우에만 쓴다.

4. **번역투를 걷어낸다.**
   - 영어 어순을 그대로 옮긴 명사 나열, 과도한 피동태, 추상명사 중심 문장을 피한다.
   - 가능하면 주어와 동작을 분명하게 쓴다.
   - 기술 용어가 이미 업계 표준이면 억지로 한국어로 번역하지 않는다.

5. **사실과 조건을 바꾸지 않는다.**
   - 자연스럽게 만들겠다고 수치, 조건, 범위, 책임, 시점, 인과관계를 바꾸지 않는다.
   - 사용자가 하지 않은 경험, 감정, 판단을 지어내지 않는다.
   - 근거가 약한 문장을 더 단정적으로 만들지 않는다.

6. **이미 자연스러운 문장은 그대로 둔다.**
   - 모든 문장을 고치려 하지 않는다.
   - 짧고 명확한 문장은 그대로 두는 것이 원칙이다.

7. **짧게 쓰려고 필요한 설명까지 없애지 않는다.**
   - 군더더기는 줄이되, 독자가 판단하는 데 필요한 전제와 예외는 남긴다.
   - 문장 수를 줄이는 것보다 이해가 쉬운지가 우선이다.

## 기본 작업 순서

1. 먼저 이 글의 독자가 누구인지 확인한다.
2. 사용자가 이미 대화에서 자연스럽게 설명한 표현이 있는지 찾는다.
3. 사실, 조건, 숫자, 금지사항처럼 바꾸면 안 되는 정보를 표시한다.
4. 초안을 쓴다.
5. 아래 항목만 다시 본다.
   - 번역투가 남았는가
   - 추상적인 홍보 문구가 들어갔는가
   - 같은 뜻을 반복하는가
   - 불필요한 비유나 과장된 대조가 있는가
   - 문장이 길어서 주어와 동작이 흐려졌는가
   - 자연스럽게 만든다는 이유로 사실이나 조건을 바꾸지 않았는가
6. 이미 자연스러운 문장은 더 손대지 않고 끝낸다.

## 문장 선택 기준

### 좋은 방향

- 구체적인 주어와 동작이 보인다.
- 한 문장에 한 가지 핵심 내용이 있다.
- 필요한 전문 용어는 그대로 쓰되 바로 이해할 수 있게 설명한다.
- 판단과 사실을 구분한다.
- 실제 업무에서 사람이 말할 법한 문장이다.

### 피할 방향

- “혁신적인”, “최적의”, “강력한”, “완벽한”처럼 근거 없는 수식어를 붙인다.
- 문서마다 “핵심은 이것입니다”, “단순히 ~가 아닙니다”를 반복한다.
- 쉬운 말을 굳이 명사형으로 바꾼다.
- 원래 없던 확신이나 감정을 덧붙인다.
- 읽기 좋게 만든다는 이유로 조건과 예외를 삭제한다.

## 대화 문장을 문서로 옮길 때

대화에서 이런 문장이 자연스러웠다면:

> 지금 문제는 기능이 없는 게 아니라, 한 파일에 너무 많은 책임이 몰려 있다는 겁니다.

문서에서는 이렇게만 다듬는다.

> 현재 문제는 기능 부족이 아니라 한 파일에 여러 책임이 몰려 있다는 점이다.

다음처럼 바꾸지 않는다.

> 현재 시스템의 본질적인 문제는 복합적 책임 구조로 인해 확장성과 유지보수성이 저해되고 있다는 점이다.

뜻은 비슷해 보여도 문장이 더 멀어지고, 독자가 바로 이해하기 어려워진다.

## 다른 스킬과 함께 쓸 때

- 문서의 **저장 위치, SSOT 여부, frontmatter, 아카이브 규칙**은 프로젝트의 문서 거버넌스 스킬을 따른다.
- 이 스킬은 **문장과 설명 방식**만 책임진다.
- 마케팅 페이지라면 copywriting 같은 목적별 스킬을 먼저 적용하고, 마지막 한국어 문장 정리에 이 스킬을 적용한다.
- 사실 검증, 출처 확인, 수치 검증은 별도 검증 절차를 따른다.

## 완료 기준

문서를 다 쓴 뒤 아래 질문에 모두 “예”라고 답할 수 있어야 한다.

- 사용자가 앞에서 물어봤을 때 이렇게 설명해도 자연스러운가?
- 문서가 되었다는 이유로 말이 더 딱딱하거나 거창해지지 않았는가?
- 전문 용어를 제외하면 굳이 어려운 말을 쓰지 않았는가?
- 과장된 대조나 광고 문구 없이도 뜻이 전달되는가?
- 사실, 숫자, 조건, 책임 범위를 그대로 보존했는가?
- 필요한 설명을 충분히 남겼는가?
- 이미 자연스러운 문장을 괜히 다시 쓰지 않았는가?
