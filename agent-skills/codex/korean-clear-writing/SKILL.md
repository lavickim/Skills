# 자연스럽고 명확한 한국어

글을 잘 쓴 티보다 독자가 내용을 이해하는 일이 먼저다. 뜻을 정확히 표현하는 평범한 문장이 있으면 그 문장을 쓴다. 의미를 늘리지 않는 수식, 비유, 재치를 덧붙이지 않는다.

## 대화할 때의 설명 방식을 글에도 유지한다

독자 한 사람이 앞에서 내용을 묻는다고 생각하고 답한다. 사용자와 대화하며 이미 자연스럽게 설명한 내용이 있다면 그 설명을 초안으로 삼는다. 사용자가 평소 대화체를 좋아한다면 ‘형에게 설명하듯’ 내용을 먼저 정리하되, 공개 글에 개인 호칭이나 둘만 아는 맥락을 옮기지는 않는다.

대화의 자연스러움은 반말이나 짧은 문장만으로 생기지 않는다. 누가 읽는지 알고, 그 사람이 궁금한 내용에 구체적으로 답하며, 앞 문장에서 생긴 의문을 다음 문장이 풀어주는 데서 온다. 이를 작성 원칙으로 삼는다. 모델 내부 원인을 입증한 설명으로 취급하지는 않는다.

문서·사이트로 옮길 때도 설명을 슬로건으로 다시 포장하지 않는다. 독자에게 필요한 배경을 보태고 존댓말과 호칭을 맞춘다. ‘전문적으로’, ‘완성도 있게’, ‘구현해’라는 요청을 추상적인 명사나 과장된 홍보 문구를 늘리라는 뜻으로 해석하지 않는다. 화면에 문장을 넣는 단계에서도 승인된 문구의 뜻과 말투를 유지한다.

‘병원 이름이 바뀌어서 홈페이지와 블로그에 새 이름을 반영했어’는 공개 사례에서 ‘병원 이름이 바뀌어 홈페이지와 블로그에 새 이름을 반영했습니다’가 될 수 있다. 이를 ‘새로운 정체성을 담아 환자와의 연결을 재설계했습니다’로 바꾸지 않는다.

## 의미를 지키면서 한국어로 쓴다

- 누가 무엇을 했는지, 독자가 무엇을 알거나 할 수 있는지 구체적으로 쓴다. 주체를 모르면 새로 만들지 않는다. ‘결과는 내일 공개됩니다’처럼 자연스러운 피동문은 그대로 둔다.
- 명사가 길게 이어지면 동사로 풀어본다. ‘정보 제공의 일관성 확보’보다 ‘같은 정보를 안내한다’가 해당 문맥의 뜻을 정확히 담는지 확인한다. 더 직접적이어도 의미가 달라지면 쓰지 않는다.
- ‘~에 있어서’, ‘~되어진다’, ‘~에 대한 진행’은 문맥에 맞게 다듬는다. ‘통해’, ‘대해’, ‘또한’, ‘것이다’를 금지어로 만들거나 발견할 때마다 치환하지 않는다.
- 독자에게 익숙한 말을 쓴다. 기술명·제품명·API·코드·URL은 정확히 보존한다. 영어라는 이유만으로 억지 번역하지 않는다. 낯선 개념은 필요한 만큼 설명한다.
- 수치, 날짜, 이름, 경력, 수상 이력, 실제 발언의 직접 인용을 문체 때문에 바꾸거나 삭제하지 않는다. 사실 수정이 필요하면 근거와 요청 범위를 따로 확인한다.
- 가능성, 의무, 조건, 부정, 인과관계, 시제를 보존한다. ‘늘어날 수 있다’를 ‘늘어난다’로, ‘확인해야 한다’를 ‘확인했다’로 바꾸지 않는다. 진행 중인 일을 완료한 것처럼 쓰지 않는다.
- 자연스럽게 들리게 하려고 경험담, 감정, 고객 반응, 성과를 만들어 넣지 않는다. 근거 없는 주장은 매끄럽게 포장하지 말고 확인이 필요한 부분으로 알린다.
- 반말·해요체·합니다체는 독자와 용도에 맞춘다. 자연스럽다는 이유로 회사 문서를 가볍게 만들거나, 격식을 갖춘다는 이유로 ‘했습니다’를 ‘수행하였습니다’로 바꾸지 않는다.

## 읽는 흐름을 다듬는다

핵심 답을 먼저 주고 필요한 배경과 이유를 이어 쓴다. 독자가 모르는 배경까지 생략한 채 짧게만 쓰지 않는다. 문장을 나누면 관계가 흐려지는 경우에는 연결해서 쓴다. 문장 길이나 종결어미를 정해진 횟수에 맞춰 섞지 않는다.

실제 차이를 설명하는 비교와 필요한 접속사는 남긴다. 원문에 없는 ‘단순한 X를 넘어 Y’, ‘X가 아니라 Y’, ‘지금이 ~할 때입니다’ 같은 대조나 결론을 멋을 위해 추가하지 않는다. 의미가 정확하고 독자에게 도움이 되는 비유는 사용할 수 있지만, 더 쉬운 직접 표현이 있으면 그것을 택한다.

소제목은 내용을 알려주고 버튼은 실제 동작을 설명한다. 목록과 표는 순서·나열·비교가 있을 때 쓴다. 요청하지 않은 FAQ, CTA, 슬로건, 강조 표시, 요약 문단을 모든 글에 붙이지 않는다. 이미 자연스러운 문장은 유지한다.

## 적용과 출력

새 글은 확보한 사실로 직접 설명하는 초안을 쓴 뒤 독자에 맞게 다듬는다. 윤문은 어색하거나 이해하기 어려운 부분만 고친다. 수정량 목표나 자연스러움 점수를 만들지 않는다.

마지막으로 읽으며 확인한다. 이 비유가 꼭 필요한가? 직접 말하는 것보다 더 명확한가? 뜻하지 않은 인상을 주지는 않는가? 더 직접적으로 쓸 수 있는가? 이어서 사실·조건·주장 강도와 말투가 유지됐는지 확인한다. 체크리스트나 내부 점검 보고를 결과물에 자동으로 붙이지 않는다.

사용자가 글을 원하면 완성한 글을 준다. 변경 제안을 원하면 실제 원문, 제안 문구, 고칠 이유를 비교하기 쉽게 보여준다. 사용자가 확인 후 반영하라고 했다면 승인 전에는 해당 파일이나 사이트를 수정하지 않는다. 이 스킬 자체가 모든 글쓰기 작업에 승인 단계를 추가하지는 않는다.

`copywriting`은 판매 페이지의 구성과 목적을 정할 때 보조로 쓸 수 있다. 한국어 표현에는 이 스킬과 사용자의 문체 요청을 적용한다. 수사적 질문·비유·재치·자신감 있는 단정을 자동으로 가져오지 않는다. 병원 글에서는 해당 작업의 사실·의학적 정확성 기준을 함께 지키되 마케팅 형식을 기계적으로 붙이지 않는다. 사용자가 의도한 문학적 문체나 특정 문체 요청은 존중한다.
